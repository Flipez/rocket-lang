# RocketLang exercises

A set of small programs that do not yet do what their comments say. Fix each one
until it prints what it promises.

```
exercises/run.sh              # stops at the first unsolved exercise
exercises/run.sh --all        # run everything, keep going
exercises/run.sh 02_strings   # one topic
```

Or in the browser, with nothing to install: pick an exercise from the dropdown
at [play.rocket-lang.org](https://play.rocket-lang.org) and press **Check**.

## How an exercise is graded

An exercise is solved when what it prints matches `expected/`. Nothing is
inspected beyond the output, so there is more than one way to solve most of them.

The expectations are **generated by running the reference solutions**:

```
go test ./exercises -update
```

That is what keeps the set honest. An exercise cannot promise output that is
impossible to produce, and a language change that breaks an exercise fails
`go test ./...` rather than being discovered by someone learning.

`go test ./exercises` checks three things without changing anything:

- every solution produces exactly the recorded output
- every exercise as shipped does **not** — an exercise that already passes asks nothing
- the playground bundle still agrees with the files on disk

## Layout

```
01_basics/01_puts.rl              the exercise, with the task in comments
solutions/01_basics/01_puts.rl    the reference solution
expected/01_basics/01_puts.txt    generated; what the solution prints
```

## The trailing nil

Every RocketLang program prints its own final value, which is `nil` as soon as
the program ends in `puts()`. That is not something an exercise asked for, so
one trailing `nil` is dropped — by the runner, by the recorder, and by the
playground, so all three agree on what "the output" is.

## Topics

| | Topic | Teaches |
| --- | --- | --- |
| 01 | basics | `puts`, variables, arithmetic, comparison |
| 02 | strings | methods, **the `!` convention**, `?` predicates |
| 03 | numbers | conversions answering `nil`, rounding, **integer bases** |
| 04 | arrays | indexing and slices, pure vs `!`, `map`/`select`/`reduce` |
| 05 | hashes | any hashable key, `get`, the undefined order, callbacks |
| 06 | control flow | `if`/`elif`/`else`, `while`, `foreach`, `break` and `next` |
| 07 | ranges | the rocket operators `->`, `=>` and `^` |
| 08 | functions | implicit return, functions as values, closures as objects |
| 09 | errors | `begin`/`rescue`, the error object, and why a failed conversion is `nil` rather than an error |
| 10 | types | `type`, `type_groups`, `is_a?`, `methods` — the language describing itself |
| 11 | matrix | a first-class matrix: `shape`, `get`/`set`, `row`, `transpose` |
| 12 | stdlib | `JSON`, `Math`, `Time` |
| 13 | capstone | three small problems using everything above |

Two are worth reading even if you skip the rest. `03_numbers/03_bases`: an
integer remembers the base it was written in, and two integers of different
bases refuse to be combined. `08_functions/03_closures`: there are no classes,
but a hash of functions closing over a constructor's locals is an object, and a
value stored under a name can be called with a dot.

## Rough edges to know about

The language is at `0.24` and a few things are missing or surprising. Exercises
avoid them, but you will meet them eventually:

- no string interpolation — `"v: #{a}"` prints literally, so build strings with `+` and `to_s()`
- no default parameters, no `unless`, no `case`/`when`
- `ensure` parses but does nothing
- a hash has no defined order, so `keys()` differs between runs
- non-ASCII strings are indexed by byte, so `"тест".size()` is `8`
- a line starting with `[` continues the previous expression, so put a blank
  line or a statement between them

Two things to know if you write your own exercise.

A program prints its own final value, and only a trailing `nil` is dropped. So
the last statement should be a `puts`, not something like `array.each(...)`,
which answers with the array.

And nothing may depend on the environment. `Time.format` uses the local
timezone, so timestamp 0 is `1970-01-01` in London and `1969-12-31` in New York
— `12_stdlib/03_time` asks about the *shape* the layout produces instead. For
the same reason no exercise uses `IO` or `OS`: there is no filesystem in the
playground, so an exercise using one would pass in the terminal and fail in the
browser.
